Glossary popups
================

Imagine you've come up with a new concept that you want to talk about in your in-house documentation so your colleagues can keep up - but it's a moderately complicated thing with several parts, and you don't want to have to keep re-defining it everywhere you mention it, or throw it in a footnote or separate document. Glossary popups can help.


Primary and secondary popups
================================
Glossary popups are a part of IntraMine's Gloss. See the dotted underline there under "Gloss"? That's how glossary terms look. Pause your cursor over "Gloss" and you'll see a *primary popup* briefly explaining what it means. Look in the resulting popup and you'll see some more dotted underlines: move your cursor over one of them and you'll see a *secondary popup* offering an additional explanation.

Here's an example if you like movies (pause your cursor over the link if you're viewing the .txt version of this using IntraMine's Viewer):
"popups.gif"

And here's a simple example of one special term mentioning another:
---
Frammistat: an arrangement of circular Interrocitors with quantum gates.
Interrocitor, Interrocitors: a solid neutronium force field generator. See "Interrocitors explained.html".
---
You'll find those definitions in "Documentation/glossary.txt", the source of glossary entries for IntraMine's documentation. If you pause your cursor over "Frammistat" you'll see its definition. And if you move your cursor into that popup and pause over "Interrocitor" you'll see its definition appear in a separate popup window, either above or below the main popup. You can even move your cursor into the "Interrocitor" popup and click on the link for "Interrocitors explained.html". Not much in there though, to be honest.

Popup overview
===============
How to show a glossary popup
----------------------------
Glossary terms have a subtle dotted underline. Here's one, Go2. Pause your cursor over the term to see the corresponding glosary entry. It's the same for secondary popups (look in the popup for Go2 and you'll see entries for Viewer and Editor that you can hover over).

Where you can use them
-------------------------
In absolutely all source or text files as displayed by IntraMine's Editor or Viewer, if you mention a term that you've provided an explanation for in a glossary entry in a glossary_master.txt (or glossary.txt, see below) file then that term will have a dotted underline in the text, and pausing your cursor over the term will show the glossary entry (the *primary* popup).

Secondary popups
--------------------
Going deeper, if a glossary entry's text mentions another glossary entry then it will acquire a dotted underline in the text of the main entry, and hovering your mouse over it will result in a secondary glossary popup being displayed, typically near the top of your window. This works everywhere that glossary popups work, even in footnote reference popups, where technically the reference popup counts as one level of popup so in this one case you're getting tertiary popups.

Two glossaries
-----------------
IntraMine has two different glossaries: one called "glossary.txt" for use when generating standalone HTML documents with the Glosser service or the gloss2html.pl Perl program, and another called "glossary_master.txt" for use with all source and text files displayed by IntraMine's Viewer or Editor. The glossary.txt file needs to be in the same folder as the .txt files that are being converted to standalone HTML, and takes precedence over the glossary_master.txt files. A glossary_master.txt file can be in any indexed location. You can have several glossary_master.txt files: they will all be combined when displaying definition popups.

You'll find details on both below. For an additional explanation of using a "glossary.txt" file to provide glossary entries for standalone HTML files, please see "gloss2html.pl for standalone Gloss files.txt".

A bit of motivation
---------------------
Why bother with a glossary? Not all projects have a strong need for one. But if it's more than just you involved, in particular if you have other developers working with you (especially ones new to the project) or if you have a manager or two, or if you have customers, or prospective investors, then instantly available definitions and procedure descriptions can help others understand your work while easing writer's block.

For an opinion from an experienced developer on whether or not you need a glossary, see
https://www.yegor256.com/2015/03/16/technical-glossaries.html
In brief: "...there is no excuse for the absence of a glossary in any software project."

With that out of the way, let's make and use a master glossary.

Making and using a master glossary
===========================
"glossary_master.txt" glossaries are for use with IntraMine's Viewer and Editor. You can have more than one glossar_master.txt file, and glossary entries from them will appear in all source and text files - *unless* a "glossary.txt" file is present in the same folder at the same level. For the point of those, see "Making and using a standalone HTML glossary" just below.

Making
------------
1. First, get IntraMine up and running, as described in IntraMine's Documentation folder. Double-click on Documentation/contents.html to get started with that, you'll see installation instructions at the top.
2. Take a look at the included example master glossary, "glossary_master.txt" included at the top of your IntraMine folder. It describes the whole glossary process and includes four example glossary entries.
3. Make a new file called "glossary_master.txt" in any **indexed location** (or contained subfolder). Your indexed locations are listed in IntraMine's data/search_directories.txt file. (Avoid the IntraMine folder though, to prevent conflicts when you next update IntraMine.)
4. Start putting glossary entries in your new file, using the format described in the the included master glossary (glossary_master.txt at the top of your IntraMine folder), or as described in "Glossary entry details" below. The simplest form of an entry is the term to define followed by a colon ":" and then the definition of the term. The definition can use Gloss, as described below.
5. Save your new glossary_master.txt file after you have an entry or two.
6. Using IntraMine (either the Search or Files page), open a source or text file that mentions one of your new glossary terms. There must be one somewhere, otherwise you wouldn't need a glossary, right? If that's tedious, use IntraMine's Search page to search for a term you just defined.
7. Look for the term and you'll see it has a dotted underline. Here's an example term so you can see what it will look like: swarm server. Hover your cursor over the term, and the definition will pop up in a "tooltip" style box. Move your cursor away, and the tooltip goes away.
8. When you save new entries in a glossary_master.txt file, they will be available after about five seconds. However, you'll need to refresh any Viewer or Editor display of a file to see the new entries.

Using
-----------
When viewing a file using IntraMine's Editor or Viewer, terms in your text that have glossary entries will be shown with a subdued dotted underline. Pause your cursor over the term to view its glossary popup. If glossary terms are used in the popup itself, they will also have a dotted underline, and pausing your cursor over one will show a secondary popup for the term.

After a glossary popup is showing, you can move your cursor over the content of the popup. There you can click on a link or select and copy text.

Making and using a standalone HTML glossary
===========================
A "glossary.txt" file contains glossary entries that will be used only for files in the same folder at the same level. They are intended for use with .txt files that will be converted to standalone .html using either the Glosser service or the equivalent gloss2html.pl Perl program. If a glossary.txt file is present, it takes precedence over any and all glossary_master.txt files as the source of glossary entries.

Making
------------
The aim is to create glossary entries for a set of related text (.txt) documents, optionally to be converted to .html as mentioned just above. A typical use would be for in-house documentation. To this end, you'll need a folder to hold the documents. In the folder at the top, create a new document called glossary.txt. Then start putting glossary entries in your new file, using the format described in "Glossary entry details" immediately below.

Using
------------
When viewing a file using IntraMine's Editor or Viewer, terms in your text that have glossary entries in your glosary.txt file will be shown with a subdued dotted underline. Pause your cursor over the term to view its glossary popup. If glossary terms are used in the popup itself, they will also have a dotted underline, and pausing your cursor over one will show a secondary popup for the term.

After a glossary popup is showing, you can move your cursor over the content of the popup. There you can click on a link or select and copy text.

Converting to standalone HTML
-----------------------------
You can use either the Glosser service or the gloss2html.pl Perl program to convert .txt files in a folder to standalone .html files, either one at a time or the whole folder. For details please see "gloss2html.pl for standalone Gloss files.txt" and "Glosser.txt" (for the Glosser service, which is easier to use).

Glossary entry details
=========================
All glossary files (glossary_master.txt, glossary.txt) use the same entry format.

Format
-----------
Summary: up to four words per term, separate any number of multiple synonymous terms with commas, follow with a colon (not escaped) and then the definition.

Note you can escape a colon by preceding it with a backslash, as in \:
Escaped colons will be ignored when looking for definitions, and the backslash will be omitted when displayed in an actual glossary popup.

Here's an example:
---
Regular expression, regex, regexp: a write-only way to match strings, or not. For example /\: ([\w'-]+)/ will crudely match a whole word, sometimes. 
---

Content
-----------------
The definition part of an entry can be plain text, text styled with Gloss, or a single image specifier in "quotes". As far as Gloss, basically everything except CODE blocks, inline HTML, and footnotes can be used in a glossary entry, as described in "Gloss.txt". Source and text and image file specifiers must be in "quotes", such as "project51/main.cpp" or "image27.png". FLASH linking for directory specifiers is also supported, and these again need to be in "quotes". If you don't like double quotes, you can use 'single quotes' instead.

Images in glossary popup entries are **displayed fully in place (inline)** rather than popping up if you hover over a link, so try to avoid huge images in your definition. This is being done mainly because images in definitions are important enough to show immediately, and also because popping them up on a hover could get confusing when there are already two levels of glossary popups.

Comment lines
-------------------
If you want a **comment line** that won't appear in the glossary definition, start the line with '##' (exactly two #'s) and then after that put anything you want, even a colon. A comment line can appear within or between definitions. For example,
##This would be a comment line: not part of a definition.

An example
------------------
An example of a definition with some synonyms:
===
Autolinks, automatic links, automatic linking, FLASH link, FLASH links, FLASH linking: Briefly, IntraMine uses a complete list of paths to Elasticsearch-indexed files, and the notion of "context", which is the folder containing the file where you are mentioning some other file, to generate a hyperlink to the file without your needing to type the full path to the file, or any special characters. Though putting links in double quotes helps readability in the original text.

You can also link to headings within other files, such as "Gloss.txt#Gloss vs MultiMarkdown tables".

That was a bit brief wasn't it? Please see Gloss.txt and Linker.txt in IntraMine's Documentation folder for more details and some examples. And autolinking_demo.pl for an example of the FLASH link algorithm.
===
(Note that ':' isn't present after the first paragraph, so the definition is three paragraphs long.)

Images on their own
--------------------
If you want to use just an image for the definition that will pop up, put the image name in quotes. For example (using <q> to stand for a quote so it won't turn into a link here):
---
CTRL+C: <q>tenor.gif<q>.
---

Multiple paragraphs
----------------------
Any definition continues down to (but not including) the next paragraph containing a colon. This means you can have multiple paragraphs in a definition, provided you avoid using a colon in any of the additional paragraphs beyond the first. If you do need a colon, put a backslash before it ( \: ). Keep in mind though that the whole glossary entry has to fit in a tooltip so briefer is better.
